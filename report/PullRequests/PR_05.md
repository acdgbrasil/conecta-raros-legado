# PR_05 - Autenticação Nativa Bun, Arquitetura IAM/DDD e Especialista Bun

## Título
Refatoração do IAM com DDD, Autenticação Otimizada para Bun e Documentação Integrada

## Contexto
Este PR representa um marco técnico significativo: a **migração completa do módulo de IAM (Identity and Access Management) para uma arquitetura orientada a domínio (DDD)**, otimizada especificamente para o runtime **Bun**. Substituímos implementações genéricas (Node.js-like) por APIs nativas do Bun (como `Bun.password`), resultando em maior performance e segurança. Além disso, integramos uma base de conhecimento massiva sobre Bun e ElysiaJS para auxiliar os agentes de IA.

## Escopo (Alto Nível)
- **IAM Core (DDD):** Implementação completa de Users, Roles e Permissions usando Entidades, Value Objects e Agregados.
- **Bun Native Optimization:** Substituição de bibliotecas como `bcrypt` e adaptadores genéricos por `Bun.password` e `Bun.env` nativos.
- **Clean Architecture:** Separação estrita em camadas de Domínio, Aplicação (Use Cases) e Infraestrutura.
- **Knowledge Base:** Inclusão de documentação técnica ("Handbooks") para Bun e ElysiaJS, e novos Agentes Especialistas.
- **Infraestrutura:** Limpeza de segredos via arquivo e migração para variáveis de ambiente seguras.

## Principais Mudanças

### 🔐 IAM & Autenticação
- **Domínio Rico:** Criação de entidades (`User`, `Role`, `Permission`) e Value Objects (`Email`, `Password`, `PersonId`) com validações de regra de negócio encapsuladas.
- **Use Cases:** Implementação de casos de uso granulares: `Login`, `CreateUser`, `ChangeUserRole`, `ListPermissions`, etc.
- **Providers Nativos:**
    - `BunPasswordHasher`: Usa a implementação nativa de Argon2 do Bun (muito mais rápida que implementações JS puro).
    - `BunJwtProvider`: Abstração limpa para manipulação de tokens.
- **Event-Driven:** Introdução de Domain Events (`UserCreated`, `UserLoggedIn`) para desacoplamento futuro.

### 📚 Knowledge Base & Agentes
- **Novos Agentes:**
    - Expansão de 2 para mais de 10 agentes especialistas (Bun, ElysiaJS, LGPD, Mongoose, PostgreSQL, etc.) integrados via `conecta-social/Agents/README.md`.
- **Handbooks:** Inclusão massiva de documentação técnica em markdown (`handbook/tooling/bun` e `handbook/tooling/ElysiaJS`) e nova estrutura de indexação para RAG (Retrieval-Augmented Generation).

### 🐘 Persistência & Limpeza
- **Remoção de Legado:** Exclusão completa de Controllers e Middlewares baseados em Hono no módulo IAM, consolidando o uso do servidor nativo do Bun.
- **Repositórios Postgres:** Implementações concretas para gerenciar o ciclo de vida das novas entidades de IAM.
- **Limpeza de Segredos:** Remoção de arquivos de segredos obsoletos (`ops/docker/secrets/*.txt`) em favor do gerenciamento via `internal_pipeline.sh` e Bitwarden.

## Riscos e Notas
- **Breaking Change:** A estrutura dos tokens JWT e das rotas de autenticação mudou. O servidor Hono legado foi removido. O Frontend precisará ser ajustado para consumir os novos endpoints.
- **Banco de Dados:** Novas tabelas e relacionamentos foram criados. É **obrigatório** rodar as migrações (`make migrate`) antes de iniciar a aplicação.
- **Dependências:** A remoção de `bcrypt` e outras libs legadas pode quebrar imports antigos que não foram refatorados (embora o compilador deva pegar isso).
