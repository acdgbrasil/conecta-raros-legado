# PR_04 - CI/CD Pipeline, Portal de Transparência e Governança Automatizada

## Título
Implementação de Pipeline CI/CD, Portal de Transparência e Especialista em GitHub Actions

## Contexto
Este PR eleva a maturidade DevOps do projeto ao implementar uma **esteira de CI/CD completa e gratuita** usando GitHub Actions. Além disso, introduz a base para o **Portal de Transparência Governamental**, gerando dados automaticamente a partir de auditorias de segurança e relatórios de maturidade de dados (CSV), alinhando o projeto às diretrizes da CGU e e-MAG.

## Escopo (Alto Nível)
- **CI/CD Automatizado:** Implementação de 3 workflows (`gatekeeper`, `release`, `notify`) para validar, versionar e deployar o código.
- **Transparência Ativa:** Criação de script TypeScript que converte CSVs de governança em JSON para consumo no Frontend.
- **Inteligência Artificial:** Criação do agente `GitHub_Actions_Specialist` e estruturação da Knowledge Base ("Bíblia") de CI/CD.
- **Segurança:** Integração com **Bitwarden Secrets Manager** na pipeline e Scan de Vulnerabilidades (Trivy).
- **Quality Gates:** Bloqueio de código que não passa no Lint ou Build nativo do Bun.

## Principais Mudanças

### 🚀 Pipelines (`.github/workflows/`)
1.  **`01-pr-gatekeeper.yml`**: Roda em todo PR. Executa Lint, Build Check, Testes de Integração e Scan de Segurança (Trivy).
2.  **`02-cd-release.yml`**: Roda na `main`. Faz Semantic Release (vX.Y.Z), builda Docker (GHCR), atualiza dados de transparência e faz deploy via SSH.
3.  **`03-notify.yml`**: Notifica o canal do Discord com patch notes formatados após cada release.

### 🏛️ Governança & Transparência
- **Gerador de Dados (`ops/scripts/generate_transparency.ts`):** Script que lê:
    - Versão do `package.json`.
    - Relatório de Segurança (JSON do Trivy).
    - Planilha de Maturidade de Dados (`tooling/mature_table_csv/`).
    - Consolida tudo em `conecta-social-front/public/data/transparency.json`.
- **Knowledge Base:** Organização da documentação do GitHub Actions em `tooling/github-actions/` para consulta dos agentes.

### 🤖 Novos Agentes
- **`GitHub_Actions_Specialist.md`**: Especialista em arquitetura de pipelines, OIDC e segurança de workflows.

## Riscos e Notas
- **Segredos:** É necessário configurar `BW_ACCESS_TOKEN` nos Secrets do repositório para que a pipeline funcione.
- **Deploy:** O workflow de deploy assume acesso SSH configurado via Bitwarden.
- **Dados:** A planilha de maturidade deve ser mantida atualizada no CSV para refletir no portal.
