# PR_03 - Reestruturação de DevOps, Automação de Commit e Modernização de Infraestrutura

## Título
DevOps 2.0: Centralização em /ops, Automação via Makefile e Assistente de Commit Semântico

## Contexto
Este Pull Request foca na organização e profissionalização da infraestrutura do monorepo. Resolvemos a poluição de arquivos de configuração na raiz, decompondo o Docker Compose para maior flexibilidade e criamos ferramentas de automação (Makefile e Git Helper) para garantir que os padrões de desenvolvimento sejam seguidos sem esforço extra.

## Escopo (Alto Nível)
- **Centralização de Ops:** Movimentação de todos os arquivos Docker, Nginx e Scripts para a nova pasta `ops/`.
- **Decomposição Docker:** Separação entre `infra` (bancos/proxy) e `app` (back/front) para permitir execução isolada.
- **Automação via Makefile:** Criação de atalhos para comandos complexos de Docker, migrações e commits.
- **Assistente de Commit:** Implementação de um script interativo que garante o padrão de Conventional Commits com emojis.
- **Modernização de Bancos:** Upgrade para PostgreSQL 18 e MongoDB 8.0.

## Principais Mudanças

### 📁 Estrutura de Pastas
- `ops/docker/`: Agora contém `compose.yml`, `compose.dev.yml` e `compose.infra.yml`.
- `ops/scripts/`: Centraliza o novo `git_commit_helper.sh`.
- `Makefile`: Central de comando na raiz do projeto.

### 🤖 Automação e DX (Developer Experience)
- `make commit`: Invoca o assistente que guia o usuário na criação de mensagens padronizadas.
- `make back`: Inicia apenas o backend e a infraestrutura necessária (economiza CPU/RAM).
- `make dev`: Inicia o ambiente completo com Hot Reload via Docker Watch.

### 🐘 Infraestrutura
- **PostgreSQL 18-alpine**: Implementado com limpeza de logs de inicialização.
- **MongoDB 8.0**: Configurado para rodar de forma silenciosa e eficiente.
- **Nginx Proxy**: Atualizado com DNS dinâmico para suportar serviços offline sem quebrar o gateway.

## Riscos e Notas
- **Reset de Dados:** Devido ao upgrade de versão do Postgres e Mongo, é mandatório rodar `make clean` (ou `docker-compose down -v`) para limpar volumes incompatíveis antes do primeiro `make dev/back`.
- **Migrações:** Após o reset, os comandos `make migrate` e `make seed` devem ser executados para reconstruir o estado do banco.
